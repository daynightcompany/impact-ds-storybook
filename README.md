# Impact DS Storybook

React + TypeScript implementation of the **SMAL Impact Design System**, converted directly from Figma to match its variants, states, spacing, and color tokens.

- **Live Storybook:** [main--6aa129bb6842c110d4d7d0d3.chromatic.com](https://main--6aa129bb6842c110d4d7d0d3.chromatic.com) — a permanent link, auto-published by GitHub Actions on every push to `main`
- **Figma source:** [SMAL Impact Design System](https://www.figma.com/design/IrtEOKkxyRBp8KnaDWRrSr/)
- **Figma Community file:** [Impact DS](https://www.figma.com/community/file/1422520357791531239)

## Tech stack

- [React 19](https://react.dev/) + [TypeScript](https://www.typescriptlang.org/)
- [Vite](https://vite.dev/) (build tool)
- [Storybook 10](https://storybook.js.org/) (component docs/preview), with [`@storybook/addon-themes`](https://storybook.js.org/addons/@storybook/addon-themes) driving the **Day / Night / SMAL** theme switcher in the toolbar
- [Chromatic](https://www.chromatic.com/) (hosting + publishing) via GitHub Actions — see [`.github/workflows/chromatic.yml`](.github/workflows/chromatic.yml)
- Plain CSS Modules — no CSS framework, no Tailwind

## Getting started

```bash
npm install
npm run storybook       # local dev, http://localhost:6006
npm run build-storybook # static build
npm run chromatic       # publish to Chromatic manually (CI does this automatically on push to main)
```

`npm run chromatic` reads the project token from the `CHROMATIC_PROJECT_TOKEN` environment variable (CI uses the repository secret of the same name). Never commit the token to `package.json`.

## Design tokens

`src/styles/tokens.css` is the full, authoritative token set for the whole library — every color, font, spacing, radius, shadow and blur value, sourced directly from Figma rather than hand-typed.

It's generated by the companion Figma plugin **[Variables to Tokens](https://www.figma.com/community/plugin/1660654514999027141)**, which reads every variable, mode, and effect/text style straight from Figma's Plugin API and outputs:

- `variables.generated.css` — ready-to-use CSS custom properties (default mode in `:root`, other modes as `[data-<collection>='<mode>']` blocks) — `tokens.css` is this file, dropped in unchanged
- `tokens.dtcg.json` — W3C Design Tokens format, one file per mode, for a Style Dictionary–style pipeline
- raw JSON — full structured data

Naming is literal (kebab-cased Figma path, no semantic renaming), and naming collisions are flagged rather than silently merged. Runs fully locally — no network access, nothing leaves Figma.

Color ships three modes, switchable live from the Storybook toolbar:

| Toolbar | `data-theme` value |
|---|---|
| Day (default) | — (base `:root` values) |
| Night | `impact-night-mode` |
| SMAL | `smal` |

Spacing, radius and text sizes also have a **Mobile** mode (375); Desktop (1920) is the default. The components only read tokens, so every size follows the mode.

- **In Storybook**, switch it with the **Breakpoint** item in the toolbar. It follows the toolbar, not the preview width, so the Viewport tool alone doesn't change it.
- **In an app**, call the `useBreakpointTokens()` hook once near the root. It follows the viewport width: Mobile below 768px, Desktop at 768px and up.

  ```tsx
  import { useBreakpointTokens } from './styles/breakpoint';

  export default function App() {
    useBreakpointTokens();
    // ...
  }
  ```

Both set `data-breakpoint="375-mobile"` on `<html>` (Desktop is the same page without it). That name lives in one place, `MOBILE_ATTRIBUTES` in `src/styles/breakpoint.ts`; update it if a tokens re-export renames it. Mobile text-style values that the plugin does not export per mode yet live in `src/styles/tokens.text-modes.css`.

### Re-exporting tokens

`tokens.css` is the plugin output, replaced as-is. Everything hand-written lives next to it and survives a re-export:

- `src/styles/tokens.extras.css` — the Google Fonts import, plus a stopgap for colors the plugin can't export yet.
- `src/styles/tokens.text-modes.css` — Mobile text-style values (stopgap).
- `.storybook/preview.css` — Storybook-only styles.

After replacing `tokens.css`, check for two known plugin defects:

1. `grep -n NaN src/styles/tokens.css` — a color whose opacity is bound to a variable comes out as `#NaNNaNNaN`, which also voids every `--shadow-shadow-*`. `tokens.extras.css` supplies those values. If nothing prints, delete its alpha-color section; if new lines print, add those tokens there (values from the Figma `theme` collection).
2. `grep -nE "^\s+--[a-z0-9-]+: [^;'\"][^;]*'[^;]*;" src/styles/tokens.css` — a value with an apostrophe (a font name like `Int'l`) is exported unquoted, which makes the production CSS build fail with a `BadString` error. It should print nothing; if it does, wrap that value in double quotes, or better, fix the name in Figma. The `theme` font-family variables use Instrument Sans / Instrument Serif in all three modes.

Also known, no action needed: `--theme-opacity-*` is exported in `px` (not usable as a CSS `opacity`, so components keep their literal values), and the `…/10` and `…/50` tints of the supportive colors are not exported.

## Continuous integration

Every push to `main` runs [`.github/workflows/chromatic.yml`](.github/workflows/chromatic.yml): it builds Storybook and publishes it to Chromatic automatically, so the live Storybook link above always reflects the latest commit — no manual publish step required.
